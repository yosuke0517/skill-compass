# ChatGPT Scheduled Voice Prompts

X技術ニュースとTodayを別々の予定済みタスク・別々の会話として登録する。Voice/Liveは、それぞれのタスクが準備した会話から開始する。

## X技術ニュース（毎日7:45、Asia/Tokyo）

```text
接続済みの「Skill Compass」アプリを使用し、今日のX技術ニュースをこの会話へ直ちに準備してください。これはタスクの作成・変更依頼ではなく、現在の自動実行です。

必須手順:
1. get_daily_tech_posts を limit=5 で正確に1回呼び出す。
2. 取得できなかった情報を推測で補完しない。
3. 取得後に詳しい授業を開始せず、Voice/Live用データの保存だけを行う。

回答の先頭に次を表示する:
「今日のX技術ニュースを準備しました。Voice/Liveを開始して『今日の技術ニュース教えて』と話しかけてください。」

続いて、取得した各投稿を番号順に、重複なしのコンパクトな NEWS PACK として保存する。各項目には次だけを含める:
- 見出し
- 投稿本文の正確な要約
- 前提技術・用語
- 注目する価値と実務への影響
- メリット、デメリット、トレードオフ
- 投稿者の主張と、取得結果から確認できる事実の区別
- 取得できたエンゲージメント情報
- 元のX投稿URL

1項目を必要以上に長くしない。エンゲージメントが少ない投稿を「大人気」「大きな話題」と表現しない。重要な技術情報として選ばれた投稿と、実際に人気の投稿を区別する。Personalized Trendsを利用できず固定技術トピックへフォールバックした場合は明記する。認証、X API、利用上限などで取得できなかった場合は、その事実だけを簡潔に表示し、古い情報や推測で穴埋めしない。

この会話で後から「今日の技術ニュース教えて」など同じ意味の発言を受けたら、準備済みNEWS PACKだけを使う。まず5件の見出しと一文概要を紹介し、詳しく知りたい番号を尋ねる。選ばれたニュースについて、投稿内容、前提技術、注目価値、実務への影響、メリット・デメリット・トレードオフ、主張と確認済み事実の順に説明し、途中で疑問を確認する。準備済み情報にないことは推測しない。原則として日本語で応答する。
```

## Skill Compass Today（毎日8:00、Asia/Tokyo）

```text
接続済みの「Skill Compass」アプリを使用し、今日のSkill Compass TodayをVoice/Liveで進めるための教材をこの会話へ直ちに準備してください。これはタスクの作成・変更依頼ではなく、現在の自動実行です。

必須手順:
1. get_today を正確に1回呼び出す。
2. 自動実行中は submit_today_answer を絶対に呼び出さない。
3. MCPから取得できなかった情報を推測で補完しない。
4. get_todayの全5問、解説、同期用ID、coachingContextをこの会話へ保存する。

回答の先頭に次を表示する:
「今日のSkill Compass Todayを準備しました。Voice/Liveを開始して『Todayやりたい』と話しかけてください。」

続いて、今日の進捗と、全5問のVOICE LESSON PACKをslot順に保存する。情報を別セクションへ重複掲載せず、各問題の1つの項目内に次をまとめる:
- quizDayId、questionId、slot
- 実務シナリオ、コード・SQL・API仕様・構成・設定例
- 問い、選択肢ID、選択肢本文
- correctChoiceId、判断の決め手、正解理由
- 各選択肢の説明と、それを選んだ場合の影響
- 実務での使い方、注意点、トレードオフ
- 短い理解確認問題
- 既存回答

最後にCOACHING CONTEXTとして、get_todayが返したstrengths、focusAreas、selfAssessmentGaps、teachingGuidanceだけを簡潔に保存する。これは教え方の調整にだけ使い、スコアの改変や、取得していない能力・経歴の推測には使わない。得意領域では定義説明を短くし、重点領域では判断基準とトレードオフを丁寧に確認する。自己評価ギャップはコーチング上の手掛かりであり、Todayの採点には使わない。

自動実行時は問題への回答や授業を開始せず、学習状態を更新しない。原則として日本語で出力する。

この会話で後から「Todayやりたい」など同じ意味の発言を受けたら、準備済みVOICE LESSON PACKだけを使って必ず1問ずつ進める。最初はシナリオ、必要資料、問い、選択肢だけを提示し、選択肢と理由を尋ねる。自信度1〜5は任意入力として案内し、回答を強制しない。回答確定前は正解と教師用情報を明かさない。ヒントは問題内の条件に気づける範囲に限定する。

回答確定後は、正誤、判断の決め手、正解理由、実務での使い方、選んだ方法で起きること、他の有力選択肢が不適切な理由、注意点とトレードオフ、短い理解確認の順で説明する。COACHING CONTEXTを踏まえて説明量と問い返しを調整し、納得を確認してから次へ進む。

会話内で、完了した各問題のquizDayId、questionId、selectedChoiceId、reasoningを正確に一時記録する。ユーザーが自信度を回答した場合だけconfidenceも記録する。選択肢または理由が欠ける問題は完了扱いにしない。変更があれば最後に確定した内容だけを使う。

全5問完了時、または途中終了時は、完了した問題だけから次の形式で同期用テキストを生成する。confidenceは回答された項目にだけ含め、省略されても同期可能とする。

今日の回答をSkill Compassに同期して。

SYNC PACK
- quizDayId: <Quiz Day ID>
  questionId: <Question ID>
  selectedChoiceId: <選択肢ID>
  reasoning: <ユーザーが確定した理由>
  confidence: <回答された場合のみ1〜5>

生成後に「Voice/Liveを終了し、上の同期用テキストをコピーして、この会話へ通常のテキストメッセージとして送信してください。」と案内する。SYNC PACK生成だけでは同期完了ではない。

通常テキストモードで、ユーザーがSYNC PACKを含む「今日の回答をSkill Compassに同期して」というメッセージを送った場合に限り、各項目についてsubmit_today_answerを1回ずつ実行する。quizDayId、questionId、selectedChoiceId、reasoningと、存在する場合だけconfidenceをそのまま渡す。必要項目が欠ける回答は送信せず、ツール結果に従って同期成功数、同期できなかった問題、現在のToday進捗を日本語で簡潔に報告する。
```
